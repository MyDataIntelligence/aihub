# aihub 1.3.0

## Wat is nieuw
- **Worktrees opschonen** (`aihub worktree cleanup`). Per worktree van deze repo en je repogroepen: grootte, laatste activiteit, niet-gecommit en niet-gepusht werk, gemerged, de PR en de story van de branch.
  - Afgeronde worktrees zonder lokaal werk staan voorgeselecteerd.
  - `--remove … [--delete-branch]` verwijdert veilig: folder-links eerst weg, nooit `--force`, nooit lokaal werk.
  - Je ziet daarna hoeveel ruimte er vrij is gekomen.
- **Lokale Robot-run** (`aihub robot local` en `aihub robot result`) achter de VS Code-knop "Run Robot Test":
  - de runner van het team (`robot.runner` of een `rf-run.py`), anders `python -m robot`;
  - de venv van de repo;
  - alleen de testomgevingen uit `robot.environments`;
  - het resultaat met aantallen, falende tests, `log.html` en `report.html`.
- **Repo-opener**:
  - `aihub repos local` geeft de lokale clones, met branch en origin uit `.git`, zonder git-proces per repo;
  - `aihub repos ado` geeft de repo's per Azure DevOps-project (team.yaml `projects`), 4 uur in de cache;
  - `aihub repos clone --repos project/naam` kloont naar de reposRoot en raakt een bestaande map nooit aan;
  - `aihub worktree groups save … --team` bewaart de groep in team.yaml.
- **Het az-token** dat binnen 15 minuten verloopt, wordt vernieuwd in een losgekoppeld `aihub token refresh`. Geen command wacht nog op az; op de werklaptop duurde dat p50 5,3 s, 17 keer per dag.

## Context
De echte performance-log van de werklaptop (VS Code 3.1.1, 23 uur) liet een processtorm in de Worktree Sets-view zien:
- op het hoogtepunt 1519 git-processen in één minuut;
- reads tot 124 s;
- elke processtart kostte daar 150–200 ms (antivirus).

De fix zit vooral in de VS Code-extensie 3.4.0. De CLI levert het vernieuwen van het az-token op de achtergrond.

## Compatibiliteit
Geen brekende wijzigingen. Nieuw in team.yaml (allemaal optioneel): `robot.runner`, `robot.environments`, `reposRoot` en `projects`.
