# aihub 1.10.1

## Wat is nieuw
- **De titel van een pull request volgt team.yaml.** `aihub pr create` geeft een nieuwe PR de titel uit `pullRequest.title`, met `{storyId}`, `{storyTitle}` en `{branch}` (#356). `--title` gaat nog steeds voor. Een patroon dat de story noemt, wordt alleen gebruikt als de story bekend is; zonder story blijft de oude titel (de eerste commit, anders de branch), dus nooit een titel als ": ". Een bestaande PR bijwerken verandert de titel niet.
- **De preview van Team Settings** (`aihub team preview --template pr`) toont nu de titel die `pr create` echt geeft. De opmerking "pullRequest.title is shown here" is weg.

## Context
Dit was het bekende probleem in de notes van PyCharm Git 0.31.0: de preview liet het titelpatroon al zien, maar `pr create` gebruikte het niet.

## Compatibiliteit
- Node 18 of nieuwer; geen daemon.
- Werkt met AI Context Hub 3.9.0 en 3.9.1 en met PyCharm Git 0.31.x; de knoppen vragen nog steeds 1.10.0 of nieuwer.
- `--json`: `team preview` geeft geen `note` en `title.createTitle` meer; die waren er alleen als de twee titels verschilden, en dat kan niet meer.
- Teams zonder `pullRequest.title` krijgen dezelfde titel als voorheen.

## Validatie
- Op de releasebron: de tests van de CLI en `lint:skills`. De telling staat in de release-PR. CI (`test`, `vscode`) was groen op #356.
- **Live bewezen tegen `ferron-test`** (synthetische testwereld, test-consumer) met de echte CLI en team.yaml `title: "{storyId}: {storyTitle}"`: PR 1282 kreeg de titel "3797: [bench-568b9d] Titel uit team.yaml" (tweede bron: `az repos pr show`). Daarna opgeruimd: PR abandoned, branch en work item verwijderd.
- **Alleen met unit-tests bewezen:** `{branch}`, dat `--title` voorgaat, een branch zonder story, en de preview.

## Installatie
`npm i -g @ferronhooi/aihub`, daarna `aihub skills install`. Of `install\Install.cmd` keuze [1] in de repository `extensions`.
