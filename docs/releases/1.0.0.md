# aihub 1.0.0

## Wat is nieuw

- Eén CLI (`aihub`) en een set Agent Skills die een codeeragent (opencode, GitHub Copilot CLI, Codex, Claude) de Azure DevOps-teamworkflows laat uitvoeren: stories maken en verfijnen volgens het sjabloon, implementeren, pull requests maken en bijwerken, reviewcommentaar verwerken, cherry-picken, branches bijwerken, pipelines volgen, releasen.
- Eén aanroep per taak: een PR maken is één `aihub pr create`, met de juiste secties in sjabloonvolgorde, de story gekoppeld en de juiste doelbranch.
- `aihub watch --mine` volgt al je eigen PR's en meldt nieuwe commentaren; `aihub open --last` pakt het gesprek weer op.
- `aihub fabric` dekt de Fabric-workflows (items, jobs, logs, failures, lakehouse, Spark, SQL, deployment) en `aihub fabric auth sp` beheert service principals.
- `aihub update` werkt de CLI en de skills bij en toont wat er veranderd is.

## Context

Deze release vervangt de AI Context Hub (VS Code-extensie, Hub CLI, JVM-core) door twee kleine onderdelen: Agent Skills die de agent vertellen wanneer en hoe, en één CLI zonder daemon die het precieze werk doet (sjablonen, doelbranch en merge base, storylinks, Azure DevOps REST-aanroepen). Er is geen MCP-server, geen achtergrondproces en geen extensie nodig. Teamkennis blijft in de teamrepository (`team.yaml`, sjablonen, PR-sjabloon), nooit in dit pakket. Zie [docs/how-it-works.md](../how-it-works.md) en [docs/parity.md](../parity.md) voor de overdracht per workflow.

## Commands overview

| Command | Doel |
|---|---|
| `pr create\|update\|changes\|explain\|checks\|requeue\|complete` | pull requests per sjabloon maken, bijwerken, bekijken, afronden |
| `comments get\|reply` | reviewthreads lezen en beantwoorden met status |
| `review show\|post` | andermans PR beoordelen en commentaar plaatsen |
| `cherry-pick --from <pr\|sha\|story> --to <branch>... [--pr]` | cherry-pick naar een of meer branches, PR per doel |
| `branch update [--rebase]` | branch bijwerken vanaf het doel |
| `story create\|show\|refine\|start\|link\|context\|finish\|template` | story-levenscyclus |
| `pipeline follow\|status\|runs\|logs\|run\|retry` | pipelines volgen, starten, herstarten |
| `batch --select "<query>" --run "<subcommand>"` | dezelfde actie op 1 of 20 items, met voorbeeldtabel |
| `work` | openstaand werk van jou |
| `watch [--pr N\|--mine] [--until ...] [--notify]` | PR's volgen en bij een gebeurtenis melden |
| `fabric ...` (incl. `logs`, `failures`, `auth sp add\|list\|remove\|default\|test`) | Fabric-items, jobs, logs, lakehouse, Spark, SQL, deployment |
| `robot` | Robot Framework-suites bepalen en draaien |
| `release plan\|run` | releasetrein vanuit samengevoegde PR's |
| `worktree create\|list\|remove` | worktrees en worktreesets over meerdere repositories |
| `repos list\|clone` | repositories van het project tonen en klonen |
| `crossrepo status\|link-prs\|test-resources` | wijzigingen over meerdere repositories |
| `init` | stelt `team.yaml` en sjablonen voor als PR, overschrijft nooit |
| `skills install\|update\|diff\|uninstall` | skills en slash-commando's in opencode, Codex en Copilot |
| `doctor` | controleert aanmelding, remote, team.yaml, sjablonen en skills |
| `update [--check]` | CLI en skills bijwerken |
| `open --last [--print]` | gesprek van de laatste gebeurtenis hervatten |
| `commit` | commit volgens het commitsjabloon van het team |
| overig | `wiki`, `workitem`, `evidence`, `port`, `note`, `status`, `explain` |

`--dry-run` toont de schrijfacties (git en REST) zonder ze uit te voeren; `--verbose` logt de echte aanroepen. Lopende tekst gaat altijd via bestanden (`--body-file`, `--replies-file`).

## Skills

`start-here`, `story-create`, `story-refine`, `story-start`, `story-run`, `story-finish`, `implement`, `commit`, `pr-create`, `pr-update`, `pr-explain`, `pr-review`, `pr-watch`, `review-process`, `branch-sync`, `cross-repo`, `worktrees`, `pipeline-fix`, `release`, `test-run`, `evidence`, `wiki`, `voice-notes`, `devops-repos`, `fabric`, `terraform`, `team-settings` en de gedeelde map `_shared`.

## Compatibility

- Node.js >= 18.
- Clients: opencode, GitHub Copilot CLI, Codex en Claude (Agent Skills-indeling).
- Windows, macOS en Linux; `az` aangemeld of een Azure DevOps-token is nodig voor de REST-aanroepen.

## Validation and evidence

- Benchmark (agent: Claude Code; het label `luna` is een stand-in, Haiku, zolang het Codex-quotum op is; arm A = aihub-skills + CLI, arm C = gewone agent met git, az en het sjabloonbestand; 7 cases, 3 runs, 2 modellen):
  - Nederlands team (`aihub-bench-20261118-final-nl`): arm A **42/42** correct, arm C 28/42.
  - Engels team (`aihub-bench-20261118-final-en`): arm A 35/42, arm C 29/42; zes van de zeven missers van A zaten in de story-case L01 (de zevende in L02). Herhaling alleen van L01 (`final2-l01-en`): A 5/6, C 3/6; (`final2-l01-nl`): A 6/6, C 3/6. Gecombineerd met de overige cases komt dat uit op 40/42 voor arm A in het Engels (29/42 voor arm C).
  - Per taak één `aihub`-aanroep, 0 vragen aan de gebruiker, doorgaans 2 tot 4 keer minder tokens en minder wandtijd dan arm C.
  - Bron: `docs/copilot-cli/aihub-bench-20261118-*.md` in de repository `MyDataIntelligence/extensions`.
- Live verificatie tegen de synthetische organisatie `ferron-test` (project `test-project`) met tweede bron `az`/`git`: [docs/live-verification.md](../live-verification.md), inclusief gevonden en gerepareerde fouten.
- Live check in opencode en Copilot CLI (geïsoleerde homes). Codex: nog niet live gedraaid (quotum).
- Fabric: alleen met fixtures getest; een live Fabric-run staat nog open.
- Runs met Luna (`gpt-6-luna`) en `gpt-6-sol` staan nog open; de benchmark gebruikt tot dan Haiku/Sonnet als stand-in en wordt later bevestigd.

## Installation

```sh
npm i -g @ferronhooi/aihub
aihub skills install --client opencode   # of github-copilot, codex, all
aihub init       # in een teamrepository
aihub doctor
```

Alleen de skills, zonder CLI: `npx skills add MyDataIntelligence/aihub -g -a opencode -a github-copilot -a codex`.

Installers: `install.ps1` (Windows PowerShell), `install.sh` (macOS/Linux) of `Install-aihub.cmd` (dubbelklikken); ze controleren Node 18+, installeren de CLI en de skills en draaien `aihub doctor`. Testversie: `npm i -g @ferronhooi/aihub@next`.

## Known limitations

- Fabric is niet live gevalideerd (alleen fixtures).
- Codex, Luna en `gpt-6-sol` zijn nog niet live bevestigd.
- Het Basic-proces van Azure DevOps kent geen Bug-type; `workitem create Bug` wordt daar geweigerd.
- In niet-interactief `opencode run` moet `permission.external_directory` op `allow` staan om de assets van de skills te lezen.
- `skills install --global` volgt `CODEX_HOME`, `COPILOT_HOME`, `OPENCODE_CONFIG_DIR` en `XDG_CONFIG_HOME`; overschrijf ze allemaal in een tijdelijke omgeving.
- Pipeline-runs en een deel van de testobjecten in `ferron-test` laten zich in Azure DevOps niet verwijderen.
