# aihub 1.0.3

## Wat is nieuw
- Optionele agents `aihub` (primair, werkt via de skills) en `aihub-runner` (subagent voor lange klussen: story-run, pipeline-fix, pr-watch, review-process; rapporteert in maximaal 5 regels) voor opencode, GitHub Copilot (VS Code en Copilot CLI), Codex en Claude Code. Ze komen mee met `aihub skills install`; `--no-agents` slaat ze over, `aihub skills uninstall` haalt ze weg, `aihub skills update` ververst ze waar ze staan, `--into-repo` schrijft `.opencode/agent/`, `.github/agents/`, `.codex/agents/` of `.claude/agents/`.
- Het opencode-formaat volgt de geïnstalleerde versie (`opencode --version`): 1.x krijgt `agent/` met een `permission`-map, 2.x en nieuwer `agents/` met een `permissions`-lijst. Bij een versiewissel verhuist `aihub skills update` de onbewerkte bestanden.
- Nieuwe client `claude` (`aihub skills install --client claude`): skills, slash commands en agents in `~/.claude/`. Hij zit bewust niet in `--client all`, omdat opencode ook `~/.claude/skills` leest en elke skill dan dubbel zou tonen.
- `aihub doctor` toont per client een regel `agents:<client>` (optioneel als ze ontbreken; een fix als de kopie ouder is dan de CLI of in de map van het andere opencode-formaat staat).
- `--client copilot` is een alias van `--client github-copilot`.
- `npm run lint:skills` controleert ook de agentbestanden: geldige front matter of TOML, maximaal 25 regels body, dezelfde body voor alle clients, geen absolute paden of echte namen, alleen bestaande skills.
- `aihub legacy remove` haalt alles weg wat de oude AI Context Hub (v1.x/2.x) op de machine zette: de oude extensie (lager dan 3.0.0), het `hub`-CLI-pakket met PATH-ingang, zijn skills, de `hub`-agent, het regelblok en de hooks voor Copilot, opencode en Codex (eigen hooks blijven), de data en per repository `.aihub`, de Hub-regels in `.git/info/exclude` en de Hub-blokken in git-hooks. Zonder `--yes` toont het alleen de lijst; `--keep-data`, `--keep-settings` en `--repos <map>` sturen wat er gebeurt. Alleen wat aantoonbaar van de Hub is (marker, gegenereerde vorm, exacte naam) gaat weg. Zie docs/legacy-removal.md.

## Context
De skills doen het werk, maar de standaardagent van een client weet niet dat hij ze moet gebruiken en vraagt vaak om dingen die een skill of `team.yaml` al beantwoordt. Wie dat wil kiest nu bewust de agent `aihub`; de standaardagent blijft ongemoeid. De agent herhaalt geen skilltekst: de skills blijven de bron van waarheid.

## Compatibiliteit
Geen brekende wijzigingen. Node >= 18. De agents zijn optioneel. Een bestand dat je zelf bewerkte, of een bestand met dezelfde naam dat aihub niet schreef, wordt nooit overschreven (zelfde regel als bij skills). Voor VS Code, Codex en Claude Code kan een agentbestand geen goedkeuring geven: zie `docs/agents.md` voor `chat.tools.terminal.autoApprove`, de Codex-sandbox en `permissions.allow` in Claude Code. De Codex-agentnaam `aihub-runner` bevat een koppelteken; de Codex-docs noemen alleen namen met een underscore, dus dat is nog niet live geverifieerd.

## Validatie
vitest (agent-installatie in nepthuismappen, nooit de echte; lint-tests) en skill-lint groen. Live met opencode 1.19.5 in een geïsoleerde home met een stubmodel: `aihub --version` en `git status` liepen zonder vraag, `git push --force` en een gewoon shell-commando werden niet toegestaan. Bewijs van de agentkiezers (opencode, VS Code, Copilot CLI) staat in het PR-verslag; Codex en Claude Code zijn alleen op bestandsniveau getest.

Daarnaast: `aihub legacy remove` is getest met vitest (neppe thuismappen, nep-`code` en nep-`reg`, echte wegwerp-git-repositories; golden bestanden van de oude Hub naast look-alikes die moeten blijven) en live in een geïsoleerde omgeving met het oude pakket uit de pre-release `legacy/hub-surface-v2-2026-11-17`: dry-run veranderde niets, `--yes` liet geen Hub-marker achter en de bestanden van de nieuwe aihub bleven byte-identiek. De user PATH in het register is alleen met een nep-`reg` getest, niet live.

## Installatie
`npm i -g @ferronhooi/aihub@latest && aihub skills install`, of `aihub update`. Kiezen: zie `docs/agents.md`.
