# aihub 1.10.0

## Wat is nieuw
- **Teaminstellingen** (`aihub team show|validate|preview|edit|init`, #314): welke team.yaml geldt (teamrepository of eigen bestand), elke sleutel met uitleg en verschillen per repository, controle met voorstellen om te herstellen, een voorbeeld van een template met de echte gegevens van de branch (er wordt niets gemaakt), wijzigen via één commit en een PR in de teamrepository (nooit main), en `init` om een teamrepository te gebruiken.
- **Run End to End, de motor** (#341, #346): teamprompts per actie (Nederlands en Engels) met de slash-commands `/story-*` en `/bug-*` voor opencode en Copilot, acceptatiecriteria met "Hoe getest" en "Bewijs" en een status per criterium, een verplichte sectie met de criteria in de PR (niet alles bewezen: eerst testen, `--draft` of `--anyway`), de voortgang van een run, YOLO met vaste grenzen, en de bar-bridge (`aihub.bar.storyAction` en verwante commando's). De namen volgen de ontwerpen (`/story-pr-review`, `/bug-run`). Een Bug heeft geen acceptatiecriteria; Fix End to End bewijst de fix met de case uit Repro Steps. De opties van het dialoog (Plan first, Fabric, Set Active) komen in de prompt; Stop zet de run stil.
- **Werken in een repository zonder kloon** (#345, #347): `browse file` haalt een binair bestand of een bestand boven 5 MB nooit op, mappen tonen groottes, en zoeken werkt zonder Code Search in de klonen op deze pc (ripgrep of git grep; er gaat niets naar Azure DevOps). `aihub browse change` is de motor van Change with Agent zonder kloon: een werkmap per wijziging met TASK.md, diff, en push als één commit op een nieuwe branch met PR, met vaste grenzen (nooit main of staging, hoogstens 20 bestanden, geen geheimen of pipeline-bestanden).
- **Zoeken en vragen over meer projecten en repositories** (#350, #351, #352): `browse search --scope` zoekt in hele projecten en gekozen repositories tegelijk (ook lokaal, binnen dezelfde scope). `aihub browse ask` stelt een vraag die alleen leest, over die scope: gelezen bestanden worden geteld (na 200 vraagt het om toestemming), voorstellen zijn hele bestanden zonder geheimen, en `apply` maakt per repository een wijziging op één branchnaam. `browse related` noemt bij een bestand de tests en de bestanden die het gebruiken.
- **Bijwerken vanaf de doelbranch op elke git-remote** (#340): `aihub branch update` is gewoon fetch plus merge en vraagt geen Azure DevOps meer. De regel noemt altijd het doel en waarom ("target staging (the branch it was cut from)"), zegt "already up to date with <doel>" als er niets te doen is, en geeft een hint `--target staging` als origin/staging bestaat terwijl er een andere branch gekozen is. De skill `branch-sync` geeft een branch die de gebruiker noemt altijd mee met `--target`.
- **Het afgeleide doel van een featurebranch** (#340, #343): een branch die van staging komt, blijft op staging. Dat geldt ook als main en staging op hetzelfde commit stonden, en ook als main later in de feature is samengevoegd. Voorheen kwam daar main uit.
- **De story-browser** (#348): elke rij toont de kolom op het bord van het team (niet alleen de status), het bord telt per kolom, een lijst geeft het totaal ("200 van N"), en een opgeslagen area op de projectwortel gebruikt de areas van het team in plaats van alles.

## Context
Deze release is de motor van de Team Settings-pagina's en van Run End to End. In PyCharm Git komen die pas in 0.31.0; tot dan zijn ze via de CLI en de commando's van de hub te gebruiken. AI Context Hub 3.9.0 hoort erbij.

## Compatibiliteit
- Node 18 of nieuwer; geen daemon.
- AI Context Hub 3.9.0 heeft deze CLI nodig voor de knoppen.
- `--json`: er zijn alleen velden en opdrachten bij gekomen (`targetReason` en `hint` bij `branch update`, `boardColumn`, `count` en `total` bij stories).
- `aihub skills install` installeert nu ook de commando's `/story-*` en `/bug-*`.

## Validatie
- Op de releasebron: de tests van de CLI en `lint:skills`. De telling staat in de release-PR. CI (`test`, `vscode`) was groen op elke PR.
- **Live bewezen** (synthetische testwereld `ferron-test`, met bench-branches en werkitems die daarna zijn opgeruimd):
  - **Team Settings**: engine en UI live 41/41, en opnieuw bewezen in een geïsoleerde run: de volledige run met 42 checks, daarna het Entry-bord 5/5 met een isolatiecheck, ook met APPDATA en LOCALAPPDATA afgeschermd (extensions #1117, #1118).
  - **Run End to End**: een nieuwe story, het criteriavoorstel (een vaag criterium genoemd), drie van vier toegepast, de story-run-prompt (nl en en), Start Work met een set, criteria vastgelegd en vanuit een andere map gelezen, voortgang, YOLO, en `pr create` met exit 5 en daarna een concept-PR met de criteriatabel tot "3/3 bewezen". Ook `stories activate`, de opties van het dialoog, en een Bug zonder criteria.
  - **Zonder kloon**: `browse file`, groottes, zoeken met Code Search en lokaal; `browse change` van start tot PR (PR verlaten, branch verwijderd).
  - **Branch update** (CLI van deze release-reeks): een lokale kale origin (bijwerken vanaf staging, "already up to date", `--target` precies gevolgd) en `ferron-test` (afgeleid doel met reden en de staging-hint): 7/7.
  - **Story-browser**: bordkolom, telling per kolom en het totaal.
  - **Een echte agent volgt TASK.md**: een opencode-agent (gpt-6-luna, afgeschermde home) voerde `browse change` uit (report.py aangepast, zonder push) en `browse ask` (zoeken binnen de scope, voorstel en rapport opgeslagen). Daarna zijn de wijzigingen naar bench-branches gepusht en opgeruimd.
  - **Zoeken en vragen over meer repositories**: `--scope` met Code Search en lokaal, en `browse related` (tests en gebruikers van een bestand).
- **Nog niet bewezen:**
  - Een volledige `/story-run` door een echte agent.
  - Stop die Escape naar een echte opencode-tab stuurt.
  - De first-parent-regel (#343): alleen met unit-tests.
  - De UI van Team Settings en Run End to End in PyCharm Git komt later (0.31.0).

## Installatie
`npm i -g @ferronhooi/aihub`, daarna `aihub skills install`. Of `install\Install.cmd` keuze [1] in de repository `extensions`.
