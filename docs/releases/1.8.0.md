# aihub 1.8.0

## Wat is nieuw
- **Pipelines voor de balk.** Nieuwe opdrachten waarmee de VS Code-extensie (AI Context Hub 3.7.0) pipelines in de titelbalk kan tonen:
  - `aihub pipeline list` geeft de runs van je branches. Bij een rode run staan de mislukte stage en stap erbij, plus het aantal mislukte tests ("1 of 148 tests failed"). "Vandaag" telt over de hele set. Die feiten van een rode run worden per run één keer gelezen en bewaard in `~/.aihub/pipeline-red-runs.json` (laatste 300), dus een tweede keer het menu openen leest niets extra.
  - `aihub pipeline show --run N` geeft de boom van stages, jobs en stappen met status, duur en link. Verder: wie of wat de run startte, de parameters, de variabelen (geheimen altijd leeg) en een samenvatting in gewone woorden.
  - `aihub pipeline log` en `aihub pipeline poll` lezen het log van een stap en volgen één run.
  - `aihub pipeline run-again --run N --plan` geeft het formulier om opnieuw te draaien: de parameters en toegestane waarden uit de YAML, de instelbare variabelen en de afhankelijkheden van stages. `--changes-file F [--commit same|latest]` start de nieuwe run.
  - Een stage die opnieuw is gedraaid, telde zijn tests dubbel ("2 of 6"). Nu telt alleen de nieuwste testrun per naam ("1 of 3").
- **Een repo is zijn remote.** Welke kloon wordt gebruikt, volgt één regel: de voorkeur, dan de laatst gebruikte, dan de eerste map waarin gezocht wordt, dan het kortste pad. Die regel geldt voor de CLI en voor de extensie. Je vindt een kloon ook via zijn remote of via een losse mapnaam, niet alleen via de mapnaam van de repository. Is er geen kloon te vinden, dan zegt de CLI dat in één zin, en de extensie biedt "Choose Folder…".
- **Geen git-variabelen van een andere repo meer.** Een git-proces dat `GIT_DIR` van een gekoppelde worktree erft (bijvoorbeeld uit een pre-commit hook, een agent of een testsuite), kon `core.bare = true` in de gedeelde config van de hoofdkloon schrijven. Geen enkel kindproces van de CLI erft nu nog `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` en verwante variabelen: niet alleen git, maar ook `dbt deps`, testopdrachten, robot, python en hooks. Een uitdrukkelijk meegegeven `GIT_INDEX_FILE` blijft wel staan. Staat `core.bare = true` er al, dan legt de CLI uit hoe dat te herstellen is.
- **Work items via het hoofdtekstveld van hun type.** Bij story refine en work item create komt de tekst in het hoofdveld van het type: bij een type met Repro Steps (zoals Bug) is dat Repro Steps, ook als Description in de veldlijst staat. Een ontbrekend teamtemplate wordt na tien minuten opnieuw gevraagd (eerder pas na 24 uur). `--refresh-template` vraagt het meteen. De skill `story-refine` zegt dit ook.
- **Foutmeldingen in één gewone zin**, ook voor de keuze van een kloon.

## Context
In 1.7.0 kwam de motor voor de story-sets in de titelbalk. Deze tussenrelease zet de pipeline-opdrachten klaar voor de volgende stap in de balk. Ook lost hij op wat de live tests en de persona-ronde van 26-11 vonden: een kloon die niet te vinden of te kiezen was, `core.bare = true` na een hook in een worktree, en een tekst in het verkeerde veld van een Bug. PR's #273 tot en met #294.

## Compatibiliteit
- Node 18 of nieuwer; geen daemon.
- AI Context Hub 3.7.0 heeft deze CLI nodig voor de knoppen in de titelbalk (met de pipeline-opdrachten). Met een oudere CLI zegt de extensie dat in gewone taal, met de opdracht om bij te werken.
- `--json`: er zijn alleen velden bij gekomen (`failedStage`, `failedStep`, `tests` op een rode run). Bestaande velden zijn ongewijzigd.
- Setbestanden en `team.yaml`: geen wijziging.

## Validatie
- Op de releasebron (staging 6c4e53d plus de versies): vitest in `cli/` en `npm run lint:skills` groen; de telling staat in de release-PR. CI (`test`, `vscode`) was groen op elke PR.
- **Live bewezen:**
  - Pipelines, rechtstreeks tegen `ferron-test` (synthetische branch): runs, show, log, plan, en een herstart via `run-again` die een nieuwe run gaf (#291). Dit liep via de argumentbouwers van de extensie met de echte CLI, niet via de knoppen: die staan nog niet in een vrijgegeven PyCharm Git.
  - Kloon kiezen in een geïsoleerd VS Code-profiel: "Choose Folder…", een kloon van een andere repo wordt geweigerd, de goede map wordt onthouden en de actie herhaald (#294).
  - Undo van een kloon met alleen-lezen git-bestanden: na 1 s verwijderd, eerder bleef hij staan (#288).
  - `scripts/live/bar.js` met de echte hub (staging 0f9a828) en PyCharm Git main: 104 PASS en 1 FAIL. De FAIL is een verouderde controle in PyCharm Git en niet van deze release.
- **Alleen met unit-tests bewezen:** dat kindprocessen geen git-variabelen erven (`git-env.test.ts`), de feiten van een rode run en "vandaag over de set" (`pipeline*.test.ts`), de regel voor welke kloon wint (`clone-rule.test.ts`, `find-clone.test.ts`), en het tienminutengeheugen voor templates.
- **Niet live bewezen:** Repro Steps als hoofdveld. Het testproject in `ferron-test` heeft geen type met Repro Steps.

## Installatie
`npm i -g @ferronhooi/aihub`, daarna `aihub skills install`. Of `install\Install.cmd` keuze [1] in de repository `extensions`.
