# AI Context Hub 3.6.0 (VS Code)

## Wat is nieuw
- **De motor achter de story-set in de titelbalk.** De extensie levert aan PyCharm Git 0.28.0 de toestand van de set (`exports.bar`, `BarState`) en de acties (`aihub.bar.*`). PyCharm Git tekent de knoppen; deze extensie doet het werk:
  - **Open Story** kiest per repo een bestaande branch van de story, ook een branch die alleen het storynummer in de naam heeft. Repo's met zo'n branch staan al aangevinkt. Een story die al open is, opent die set opnieuw in plaats van een tweede set te maken.
  - **Een branch met een worktree elders**: één korte vraag met vier keuzes: Move (aanbevolen), Reuse, Recreate en Open in Its Own Window. Per keuze staat er één regel die zegt wat er gebeurt en waar.
  - **Update All, Commit All…, Push All… en Create Pull Requests…** over de hele set, met één resultaatregel per repo. Commit All commit alleen wat genoemd is; Push All pusht alleen story-branches, bij naam. Update pusht nooit.
  - **Open in Own Window…**: één repo van de set als losse kopie in een eigen venster. De set en dit venster blijven zoals ze zijn.
  - **Undo na elke actie die een set verandert** (Open Story, toevoegen, weghalen, wisselen, bijwerken, ook na het met de hand bewerken van het setbestand). Er is precies één melding per actie, in gewone woorden, met Undo. Undo gooit nooit commits weg, bewaart genegeerde bestanden en maakt alleen de branches van die ene actie ongedaan. De laatste Undo staat op schijf, dus elk venster toont dezelfde.
  - **Achter op de doelbranch** (`aiContextHub.behindTarget`: `ask` (standaard), `auto`, `off`). Je krijgt één melding per repo, of per set: "repo-a is 14 commits behind staging · no conflicts", met Update / Later. Met `auto` wordt een repo zonder conflicten en zonder overlap met niet-gecommit werk vanzelf bijgewerkt, met één regel en Undo. Bijwerken pusht nooit en gebeurt nooit tijdens een merge, rebase, cherry-pick of revert.
  - **De set zet nooit uit zichzelf een andere repo terug.** De echte HEAD van een repo wint, en de toestand volgt ook wat je in een terminal of in de Git-extensie van VS Code doet.
  - **Een set blijft een set.** Is het setbestand even onleesbaar (geen geldige JSON, wordt net vervangen, een scanner houdt het vast), dan houdt de balk de laatste goede set aan en zegt `BarState.setFileProblem` waarom. Is het bestand weer leesbaar, dan volgt de balk vanzelf. Eerder viel de balk terug op de weergave van een losse repo.
  - **Na Move, Reuse of Recreate staat de repo één keer in de set** (aihub 1.7.0); eerder kon er een tweede regel `repo-a--orderexport-2` bij komen.
  - **Een branch die in de kloon zelf is uitgecheckt** (bijvoorbeeld `main` via Other Branch of Checkout): één korte vraag "<branch> is checked out in the clone", het pad één keer en "Open That Folder in Its Own Window". Geen opdrachtregel meer in de melding.
  - **Een met de hand ingevulde branch die git niet kent**: één vraag "<branch> does not exist in <repo>" met "Create It from <doelbranch>" of "Put the File Back" (Escape zet alleen die regel terug). Een branch die alleen op de remote staat, wordt zonder vraag gebruikt.
  - **Grootte en "all merged"** per set in het linker menu: hoogstens één meting per dag, met een tijdslimiet. Verwijderen vraagt eerst of de set schoon is.
- **Reacties op pull requests in de code en in de Explorer** (instelling `aiContextHub.prComments`, standaard `on`):
  - elke thread van de PR's van de set staat op zijn regel in het bestand: auteur, tijd, status (`Active`, `Outdated`, `Resolved`), antwoorden, en een antwoordvak met Reply en Resolve;
  - een ```` ```suggestion ````-blok geeft **Apply Suggestion**: een gewone bewerking van het open document (Ctrl+Z), die nooit wordt opgeslagen of gecommit;
  - de Explorer toont het aantal open threads op het bestand en op elke map erboven;
  - een nieuwe reactie van iemand anders geeft één melding, en nooit een melding voor je eigen reacties.
- **De statusbalk heeft geen timer meer.** Hij leest 5 s na het openen, bij een branchwissel van de eerste map, en bij focus terug als de laatste lezing ouder is dan 5 minuten. Zonder focus leest hij nooit. Fabric wordt alleen gevraagd als `team.yaml` een `fabric:`-sectie heeft.
- **Een CLI die te oud is of ontbreekt** geeft een gewone zin met de gevonden en de nodige versie, en de knoppen Copy update command / Update now. Je ziet nooit de gebruikstekst van de CLI.

## Snelheid
Gemeten in een echt venster met een set van 5 repo's, met `scripts/live/setSpeed.js` in PyCharm Git (git-starts per fase):

| Fase | 3.5.0 met PyCharm Git 0.27.1 | 3.6.0 met PyCharm Git 0.28.0 |
|---|---|---|
| rust (60 s, geen focus) | 8 tot 16 | 0 |
| opslaan | 9 tot 10 | 1 |
| één repo wisselt van branch | 31 (101 met een tussenversie van de motor) | 10 |
| set openen (30 s) | 63 tot 65 | ongeveer 64 |

In 3.6.0 zit geen timer in de statusbalk, en er is geen lezing zonder focus. Een mislukte lezing wordt 5 minuten onthouden. Reacties op PR's worden alleen gelezen voor repo's met een actieve PR, één `aihub comments threads` voor de hele set; rust en bestanden openen kosten 0 processen.

## Compatibiliteit
- Vraagt aihub 1.7.0 voor de knoppen in de titelbalk (die nieuwe commando's zoals `aihub recent` en `aihub comments threads` gebruiken). Met een oudere CLI zegt de extensie dat in gewone taal, met de opdracht om bij te werken. De bestaande statusbalk en de panelen werken ook met een oudere CLI zoals in 3.5.0.
- De knoppen zelf staan in PyCharm Git 0.28.0. Zonder PyCharm Git doet de extensie wat 3.5.0 deed, plus de reacties op PR's en de statusbalk zonder timer.
- De velden in `BarState` die PyCharm Git 0.27.x las, zijn ongewijzigd. Er zijn alleen velden bij gekomen.

## Validatie
- Typecheck en unit-tests groen op de releasebron (zie de release-PR voor de telling). CI (`test`, `vscode`) groen op elke PR.
- Telling van processen per fase met de echte `registerBar` op tijdelijke repo's (`bar-real-budget.test.ts`): rust 0, opslaan 0, één branchwissel 1 git.
- Live in een geïsoleerd VS Code-venster (eigen profiel, synthetische repo's) met PyCharm Git: `scripts/live/bar.js` met de echte hub, 100 PASS en 0 FAIL op de laatste PR's. De controle op precies deze releasebestanden staat in de release-PR.
- Reacties op PR's live getest tegen een synthetische PR in `ferron-test`: plaats, Reply, Resolve, Apply Suggestion, Outdated, meldingen en badges. Dat het nooit een melding geeft voor je eigen reacties, is alleen met unit-tests bewezen.
- Persona-test (story-sets in de balk): niets verloor werk. De gevonden punten staan hieronder.

## Known issues
- Open Story faalt als een repo meerdere klonen heeft en de gekozen kloon een andere mapnaam heeft dan de repository ("repository '…' not found next to …"). Welke kloon gebruikt wordt, is niet te zien en niet te kiezen.
- Een wissel met niet-gecommit werk wordt geweigerd met een technische tekst (een CLI-vlag, `--mode worktree`). Het werk blijft wel intact.
- Een verplaatste of verwijderde bronkloon geeft bij Update All een kale git-fout (`fatal: not a git repository`) zonder uitleg; de rest van de set werkt en blijft heel. De map terugzetten herstelt het.
- De melding "achter op de doelbranch" en het overzicht met echte waarden zijn alleen in tests bewezen, niet in een venster met focus.
- De verbeteringen uit PR #272 (één regel per repo na Move/Reuse/Recreate, een set blijft een set, de vraag bij een branch in de kloon of een onbekende branch) zijn met tests bewezen, maar nog niet in een persona-ronde.
- De zoekfunctie voor remote repo's en voor branches die ergens zijn uitgecheckt, zit in de motor (`BarState.checkouts`, `branchRefs`, `remote`, `aihub.bar.cloneRepository`), maar de balk toont hem nog niet. Dat komt in een volgende release van PyCharm Git.
- Een set van 5 repo's openen kost nog ongeveer 64 git-starts. Een verbetering is onderweg.

## Installatie
`Install-Extensions`, of `code --install-extension ai-context-hub-3.6.0.vsix` (controleer de sha256). Installeer aihub 1.7.0 erbij: `npm i -g @ferronhooi/aihub`.
