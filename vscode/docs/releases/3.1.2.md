# AI Context Hub 3.1.2 (VS Code)

## Wat is nieuw
- **Worktree Sets start veel minder git-processen.** De view las de status van de hele set opnieuw voor elke repo-rij: repos x repos x 6 git-processen per verversing. Nu wordt een set een keer per verversing gelezen en delen de rijen dat antwoord. Een set van 5 repos: 30 processen in plaats van 150.
- **De statusbalk past zich aan een trage machine aan.** Een automatische refresh (timer, focus, branchwissel) wacht minstens tien keer zo lang als de vorige read duurde, hoogstens 10 minuten. Een snelle read (1 s) verandert niets. "Refresh" met de hand wordt nooit uitgesteld. In het performance-rapport staan de overgeslagen reads als `refresh.skip.<reden>.backoff`.

## Context
Op de werklaptop (VS Code in een VM, met antivirus) is een proces starten duur: een `git`-aanroep is daar ongeveer drie processtarts. 3.1.1 bracht de refresh terug naar een proces; dit zijn de twee plekken die overbleven. De regels hiervoor staan nu in `AGENTS.md` onder "Speed".

## Compatibiliteit
Geen wijziging: werkt met aihub 1.0.2 of nieuwer, een proces per refresh met aihub 1.0.9. De CLI is niet gewijzigd.

## Validatie
- Typecheck en 112 unit-tests groen, waarvan 5 nieuw: de gedeelde statusread (een set van 3 repos wordt een keer gelezen, na verversen opnieuw) en de back-off (trage read stelt uit, handmatig niet, snelle read ongewijzigd, maximum 10 minuten).
