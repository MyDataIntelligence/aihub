# Changelog

One `## <version>` heading per release, one bullet per change. `aihub update` shows the bullets between the old and the new version.

## 1.0.4
- `aihub pipeline approvals approve|reject` now refuses ACC and PRD approvals even though the Azure DevOps answer names no environment: the environment is read from the run's pipeline YAML, and the command refuses when it cannot tell (give `--allow-env <stage>` only when the developer asked for that stage).
- Pipelines proven live in ferron-test: `pipeline artifacts --download` now downloads pipeline artifacts (published with `publish:`) from the artifacts host, `pipeline approvals list|approve|reject` finds the environment of an approval (through the run timeline) so the ACC/PRD guard sees its real name, and `pipeline env checks` prints an approver known only by id.
- Learn, slice 2: personal store `aihub learn save|list|show|forget|concepts|quiz` (~/.config/aihub/learn, nothing in the repository) and, in the VS Code extension, the Learn view, a lesson page with rendered Mermaid pictures and a guided tour.
- Learn, slice 1: `aihub learn change|repo|validate` (facts of a change or repository as JSON in about a second: hunks, changed names, callers, tests, dbt lineage; schema check of a written explanation), skill `learn` and `/leer` that write the lesson with Mermaid pictures first. See docs/learn.md.
- dbt support: `aihub dbt detect|check` (project, adapter, versions, setup problems), `aihub dbt <build|run|test|compile|seed|snapshot|show|ls|deps|debug|parse|retry|freshness|docs|run-operation>` on the local dbt CLI with selectors, `--state`/`--defer`, compact output and `--json`; `aihub dbt failures` (failed test, compiled SQL, first failing rows), `aihub dbt lineage`, `aihub dbt impact [--base] [--state <dir>|auto] [--write]` (changed models, downstream models, tests, exposures, Fabric items; code-owned PR section), `aihub dbt yaml check|scaffold` (model entry or unit-test skeleton). `aihub test changed` plans dbt builds for changed models (`tests.dbt` in team.yaml). New skill `dbt` with a reference; implement, pr-create and test-run point to it. Writes on a Fabric adapter stay behind `aihub fabric dbt run --workspace`.
- Feasibility mode: skill `feasibility` and slash commands `/kan-dit` and `/can-it` research whether an idea is possible (docs, community, live probes) and answer with a fixed report (Verdict, Hoe, Bewijs, Bronnen, Grenzen, Inschatting, Open vragen). New subagent `aihub-researcher`. New read-only `aihub probe fabric endpoint|capacity`, `aihub probe devops feature`, `aihub probe api --get <url>` (YES/NO/UNKNOWN with the raw status, never item contents) and `aihub research save --file report.md [--wiki <page>]`. See docs/feasibility.md.

- The opencode `aihub` and `aihub-runner` agents allow by default (shell commands, edits, reads, web fetches) and deny only a short dangerous list (force pushes, direct pushes to main/master/staging/release/*, `rm -rf /*` and `~*`, `az ... delete`, `curl | sh`; `git reset --hard` asks); `aihub-researcher` stays read-only. `aihub skills install` prints the matching auto-approve settings for Copilot/VS Code, Codex and Claude Code (documented in docs/agents.md). Every aihub agent says never to use the old `hub` CLI; `aihub doctor` reports `legacy-hub` (the old hub CLI, skills, rules, hooks still installed) with the fix `aihub legacy remove --dry-run`, and `aihub skills install` warns the same.
- Azure DevOps test plans and artifacts: `aihub testplan plans|suites|cases|points|outcome|runs|results|create-plan|create-suite|create-case` (plans, suites tree, cases, points with outcome counts, test runs and results of a build with the failures first, create and set outcome) and `aihub artifacts feeds|packages|versions` (read only). `--json` everywhere, writes `--dry-run`. New skill `devops-boards` (work items, boards, test plans, artifacts).
- Fix memory: `aihub fix known [--run <id|link> | --error "<text>"]` looks the error up in the team's `known-fixes.md` (team pack, `.agents/skills/_shared/references/`), matching the error line without numbers, ids and paths; `aihub fix remember --error "<line>" --fix "<1-3 lines>"` proposes a new entry as a pull request from a throw-away worktree (nothing is stored silently, your checkout is untouched). The pipeline-fix skill asks `fix known` first and offers `fix remember` after a non-obvious fix. `aihub team learn "<rule>"` proposes a team rule the same way (first file under `guidelines:` in team.yaml, else `team-knowledge.md`). `aihub crossrepo impact --from <pr|sha>` maps the changed files through `crossRepo.pathMaps` and `repositories[]` and says which files exist in the local clones of the other repositories (read-only).
- PR helpers: `aihub pr comment --closed --title ... [--link-section Resultaat]` (a detail comment as a closed thread, linked from a section), `aihub pr tests add --from-run|--from-robot|--from-fabric-job` (an honest row in the PR test table from the real run) and team.yaml `pullRequest.afterCreate: {storyState, autoComplete}` executed by `pr create` (auto-complete only when the target branch has a blocking policy).
- `aihub watch --run <id|link> | --robot <build> | --fabric-job <workspace/item/job id> [--notify]`: follows one long run in the background (detached like `watch --mine`) and reports the result, with the Fix button (`/fix ...` for the aihub agent) when it failed on a feature branch (not protected, not a PR merge build). The skills pipeline-fix, fabric, test-run and story-run now say "ik volg het op de achtergrond" and use it instead of blocking on `--wait` or `pipeline follow`, which stay for explicit requests. `aihub fabric run` prints the watch command.
- `aihub fabric logs` without `--workspace` resolves the branch workspace itself (same rule as `fabric failures`).
- `fabric sql` runs natively again on the lakehouse SQL endpoint (tedious 19.2, token audience with trailing slash, `--item <lakehouse>` no longer ambiguous with its SQL endpoint); `fabric spark stop` really stops a session (item id and lower-case item type of the real API) and `--all-mine` is limited to your own sessions.
- `aihub standup [--since yesterday|today|<duration>]`: 3 to 5 lines from your commits, PRs (created, merged, updated), reviews you commented on, builds and story state changes (on a Monday `yesterday` means Friday); `aihub handoff [--to <name>] [--clipboard] [--wiki]`: your open work as a short markdown note (open PRs with votes, threads and build, stories, branches not pushed, running watches, failing runs). Both read-only, in the team language from team.yaml (nl or en); `--wiki` is the one write and only on request. New skill `standup` with `/standup` and `/handoff`.
- Pre-review of someone else's PR: `aihub review prepare --pr N` gives the agent the diff (numbered lines), threads and the file for its findings; skill `pr-review` writes numbered findings (severity, file:line, suggestion) there and shows them; `aihub review post --pr N --pick 1,3,5` posts only the chosen ones as threads on the right lines. Without `--pick` nothing is posted. The old `--comments-file` route is unchanged.
- `aihub watch --mine` also watches your own builds: a failed build on your own feature branch (never main, staging, release) raises a toast with a Fix button; it opens the chat with the `aihub` agent and `/fix <run url>`. New `/fix` command and skill `pipeline-fix` (works without a story): `aihub pipeline logs --failed [--run <id|url>]` prints branch, protected flag and red rounds first and says STOP on a protected branch or after 3 red rounds; flaky or infrastructure causes are reported, not fixed. Fabric runs: `aihub fabric failures`. Release notes: docs/releases/1.0.4.md.
- `aihub release plan --from DEV --to ACC [--out plan.yaml] [--notes-out notes.md]`: what moves from one environment to the next, read only: items new/changed/deleted (Fabric deployment pipeline stages and git), per item the PRs and stories, the cherry-pick list, generated release notes in the team language; `fabric.environments` and `fabric.deploymentPipeline` in team.yaml.
- `aihub pr data-diff [--pr N] [--write]`: read-only before/after numbers (count, nulls, sums, distinct, custom SELECT per table, `dataChecks:` in team.yaml) from the baseline and the feature workspace as a table with deltas and a verdict; `--write` puts it in the PR section "Data before/after". Never ACC/PRD. Release notes: docs/releases/1.0.4.md.

## 1.0.3
- `aihub legacy remove [--yes] [--keep-data] [--keep-settings] [--repos <dir>]`: lists, then removes, everything the old AI Context Hub put on the machine (extension below 3.0.0, `hub` CLI package and PATH entry, its skills, agent, rules block and hooks, data, per-repo `.aihub`, exclude lines and git hook blocks); only what is provably Hub-owned, your own files and hooks stay. See docs/legacy-removal.md.
- `aihub init` also proposes `.github/instructions/<area>.instructions.md` skeletons (`applyTo:` front matter, empty rule bullets, for the file types the repository really has) and a marked aihub block in `AGENTS.md` (created, or appended only when the file has no aihub line); each only when missing. `--no-instructions` and `--no-agents-md` skip them.
- `aihub comments reply --reply "<threadId>:<status>:<text>"` (repeatable, no file needed; an agent whose shell may not write files can still answer threads) and a value that starts with `- ` (a markdown bullet, for example `--append-text "- item"`) is accepted after its option.
- `aihub pr list [--mine|--reviewer|--branch] [--status] [--repo] [--json]`, `aihub pr show --pr N [--json]`, reviewers with votes in `aihub status --json` (`pr.reviewers`) and `aihub watch events [--limit] [--since] [--json]` for tools such as the VS Code extension. Shapes: docs/cli-json.md.
- Optional `aihub` and `aihub-runner` agents for opencode (format follows the installed 1.x or 2.x), GitHub Copilot, Codex and Claude Code (`--client claude`, opt-in), installed by `aihub skills install` (`--no-agents` skips, `--into-repo` writes them into the repository, an edited file is never overwritten); `aihub doctor` reports them. Release notes: docs/releases/1.0.3.md.

## 1.0.2
- `/story-run` slash command; `aihub test changed [--run]` runs only the tests for changed files; skills never run the whole suite locally; `aihub commit` names the git hooks it runs and how long they took, `--no-verify` only on request. Release notes: docs/releases/1.0.2.md.

## 1.0.1
- `pr create` fills an empty Changes section from the commits and an empty Tests section with an honest "not run yet"; the agent's text is never overwritten.
- Skills are self-contained (no `_shared` links), so `npx skills add` gives the same skills as `aihub skills install`. Release notes: docs/releases/1.0.1.md.

## 1.0.0
- First stable release: replaces the AI Context Hub with Agent Skills and one daemonless CLI (no MCP). The 0.1.0 command set plus `watch --mine`, `open --last`, `commit`, `repos`, `crossrepo`, `worktree`, `release`, `review`, `wiki`, `workitem`, `evidence`, `port`, `status` and the full `fabric` family (`logs`, `failures`, `auth sp`).
- Benchmark nl: 42/42 correct with aihub against 28/42 for a plain agent, one aihub call per task, no questions. Release notes: docs/releases/1.0.0.md.

## 0.1.0
- `aihub pr create|update`, `comments get|reply`, `story`, `branch`, `cherry-pick`, `pipeline`, `batch`, `work`, `fabric`, `robot` and the other workflow commands.
- `aihub init` proposes team.yaml and the templates as a pull request; it never overwrites a file.
- `aihub skills install|update|diff|uninstall` copies the bundled skills and slash commands into opencode, Codex and Copilot.
- `aihub doctor` checks sign-in, remote, team.yaml, PR template, guideline files and the installed skills.
- `aihub update [--check]` updates the CLI and the skills; `aihub explain <command>` describes a command step by step.
- `--dry-run` prints the writes (git and REST) a command would do; `--verbose` logs the real calls.
- One-line installers (install.ps1, install.sh, Install-aihub.cmd), docs/self-hosting.md and azure-pipelines.yml for teams that run aihub from their own feed.
- `team-pack/`: the copy-ready team files (also the source of `aihub init`), attached to each GitHub release as aihub-team-pack-<version>.zip.
- guidelines: in team.yaml: repository files the agent reads first.
